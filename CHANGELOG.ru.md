# Журнал изменений

Здесь документируются значимые изменения. Формат основан на Keep a Changelog и Semantic Versioning.

## [1.8.0] — 2026-08-17

### Добавлено

- Получение всех Jira-проектов, доступных авторизованному пользователю Atlassian, через встроенный MCP-сервер.
- Рабочая вкладка «Проекты» для выбора проектов, опрашиваемых и анализируемых по расписанию.
- Отдельная вкладка документа для каждого выбранного проекта с режимами Backlog и Sprints.
- Переключатель русского и английского языков в шапке с сохранением выбора в браузере.

### Изменено

- Синхронизация создаёт отдельный Markdown-снимок для каждого выбранного проекта, сохраняя совместимость со старым выходным файлом при выборе одного проекта.
- Ключ шифрования OAuth теперь хранится рядом с сессией в приватном Docker volume, поэтому перенос проекта и пересоздание контейнера не приводят к расхождению ключей; нечитаемая legacy-сессия изолируется вместо падения MCP healthcheck.
- Выбранные проекты и необязательный базовый адрес Jira перенесены из конфигурации группировки в `data/workspace.json`; значения из интерфейса имеют приоритет, а адрес Jira изменяется на вкладке «Интеграция».
- Секции `document` и `grouping` больше не обязательны: параметры документа вычисляются для каждого проекта, а правила группировки по умолчанию редактируются и сохраняются через workspace вкладки «Конфигурация».
- Backlog больше не группируется по спринтам и без явных правил является плоским списком; настройки изолированы по проектам, Sprints использует отдельный документ, а анализатор добавляет новые темы по метаданным синхронизированных задач, не заменяя существующие.
- Темы анализатора теперь пересматриваются при каждом запуске: ручные темы сохраняются, а правила с `source: "analyzer"` строятся заново по актуальному снимку проекта.
- Keyword-анализатор заменён семантической LLM-классификацией. Ollama используется по умолчанию; во вкладке «Интеграция» доступны зашифрованное подключение OpenAI-совместимой внешней модели и явный переключатель провайдера.

## [1.7.0] — 2026-08-16

### Добавлено

- Встроенный read-only Jira MCP sidecar на официальном MCP SDK.
- Браузерная Atlassian OAuth 2.1 авторизация через официальный Rovo MCP с PKCE и dynamic client registration без ввода Client ID или Client Secret.
- Хранение токенов с шифрованием AES-256-GCM в приватном Docker volume и генерируемым launcher ключом.
- Встроенный Jira MCP теперь является единственным провайдером; legacy-запуск Docker MCP Gateway и code-mode удалены.
- Внутренняя авторизация, проверка Origin, ограниченные повторы при rate limit, healthcheck, тесты и аудит зависимостей нового сервиса.

## [1.6.0] — 2026-08-16

### Добавлено

- Кнопка копирования у каждого заголовка задачи с одновременной записью rich HTML и обычного текста.
- Сохранение кликабельной Jira-ссылки для Confluence и OneNote и явного URL для текстовых редакторов.
- Визуальное подтверждение, fallback для старых Clipboard API и автоматический тест сохранения URL.

## [1.5.0] — 2026-08-15

### Добавлено

- Подсказки существующих меток и каталог меток в панели задачи.
- Счётчики использования и подтверждаемое удаление метки из всей системы с автоматической перегруппировкой документа.
- Тесты построения каталога и регистронезависимого глобального удаления.

## [1.4.0] — 2026-08-15

### Добавлено

- Отдельная вкладка «Спринты» на базе существующего просмотрщика со структурой, поиском, сворачиванием, комментариями и метками.
- Клиентское преобразование иерархии Goal → направление → размещение в размещение → Goal → направление без дополнительного запроса к Jira.
- Автоматический тест порядка спринтов и сохранения иерархии.

## [1.3.0] — 2026-07-29

### Изменено

- Выбор первой темы по regex заменён взвешенной классификацией по заголовку, Jira labels, components и описанию.
- Введены направления для runtime-платформы, developer platform, cloud/IaC, безопасности, observability, данных, сети, reliability, FinOps, исследований и legacy.
- Задача с локальными метками теперь отображается во всех группах своих меток; метки по-прежнему полностью перекрывают themes.
- Goal сохранён обязательным верхним уровнем, включая группу для пустого Goal; порядок размещения остаётся активный/будущий/бэклог.
- Счётчик Goal считает уникальные задачи при попадании задачи в несколько групп меток.
- macOS launcher теперь ожидает завершения предыдущей launchd-службы Gateway перед повторным использованием её имени и лога.

## [1.2.0] — 2026-07-29

### Добавлено

- Локальные метки с управлением в панели задачи и чипами возле заголовка.
- Приоритет меток: первая метка перекрывает группировку по themes при генерации документа.
- Автоматическая перегруппировка после изменения меток и очистка меток исчезнувших задач.
- Тесты хранилища меток и приоритета группировки.

## [1.1.0] — 2026-07-29

### Изменено

- Проект и репозиторий переименованы в TeamWork.
- Сервис по умолчанию привязан к localhost; добавлена опциональная HTTP Basic-аутентификация.
- Доступ к документам ограничен runtime-каталогом `data`.
- Контейнер усилен read-only root filesystem, сбросом capabilities, `no-new-privileges` и healthcheck.
- Добавлены функциональные тесты авторизации, ограничения путей и локальных комментариев.
- Перед остановкой старого Gateway теперь проверяется PID и команда процесса.
- Жизненный цикл Gateway в macOS передан `launchd` и больше не зависит от терминала запуска.
- Прямой запуск Compose без MCP-токена заблокирован; launchd получил PATH к Docker Desktop credential helper.

## [1.0.0] — 2026-07-29

### Добавлено

- Интеграция с Docker MCP Gateway и OAuth Atlassian из профиля Docker Desktop.
- Синхронизация Jira по расписанию и настраиваемая генерация Markdown.
- Группировка верхнего уровня по Goal, затем по теме и расположению задачи.
- Просмотрщик со структурой, поиском, scroll-spy и сворачиванием разделов.
- Локальные комментарии с выводом под задачей, панелью управления и автоочисткой.
- JSONL-логирование и просмотр журнала в интерфейсе.
- Документация на английском и русском языках.
- CodeQL, dependency review, npm audit, Dependabot и настройки безопасности репозитория.
